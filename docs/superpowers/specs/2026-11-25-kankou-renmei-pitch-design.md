# 福井県観光連盟への持ち込み準備 設計書

2026-11-25 / 会長と相談して作成（承認待ち）

## 1. ねらい

最終目標は変わらず「福井県の公認ゲーム」になること（会長より）。

調べた結果、県には「ゲームそのものを承認する」仕組みが見当たらなかった。
- 後援名義は大会・行事などイベントが対象（県スポーツ課・坂井市・内閣府の要綱）。会長はリアルイベントは難しい。
- はぴりゅうの名称使用は、イベント名に使う場合で、県の後援が前提。
- 「地味にすごい、福井」ロゴは届出制で、規程に「県による推奨ではない」とある。

そこで、申請書で承認をもらうのではなく、**県に近い団体に協力してもらい、そこから県へつないでもらう**やり方に切り替える。入口は福井県観光連盟（会長が選択）。ゲームはすでに観光連盟の越前おろしそば特集へ案内しているので、話のきっかけがある。

最大の強みは **福井県立高志高校の探究活動** であること（会長より）。

## 2. ゴール / やらないこと / 失敗とみなすこと

**ゴール**
- 観光連盟の担当者がゲームを開いたとき、「誰が・何のために作ったか・内容は正しいか」がすぐ分かる状態にする
- 観光連盟に送る提案書と最初のメールを用意する
- お願いは3つ: ①豆知識の内容チェック、②OKなら「協力：福井県観光連盟」と表示する許可、③サイトやSNSでの紹介

**やらないこと**
- 県へ直接の申請や、県へのつなぎを最初から頼むこと（関係ができてから）
- 実在店の掲載（方式Cのまま）
- メールの送信。送るのは会長（と先生）

**失敗とみなすこと**
- 高校生のフルネームや個人の連絡先がゲーム画面に出る
- 学校や先生の了解なく学校名を出す
- 「公認」「協力」など、まだもらっていない肩書きを書く

## 3. 進め方の選択肢（決定済み）

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| 後援名義（イベント） | 大会を開いて後援をもらう | 承認書がはっきり残る | 対象はイベントだけ。リアルは難しく、オンラインは前例が不明 |
| 県へ直接提案 | 県の観光・ブランド担当課に送る | 公認に一番近い | 窓口がなく、後回しにされやすい |
| **観光連盟から入る（採用）** | 協力をもらってから県へ | きっかけがある。断られても次に県へ行ける | 県の承認まで一段多い |

## 4. 決まっていること

### 4.1 名乗り方
- 提案書・メール: 本名＋高志高校＋担当の先生のお名前。先生にCCか連名で入ってもらう（こちらの提案、会長了承待ち）
- ゲーム画面: 「福井県立高志高校 探究活動」＋名字のみ、または班の名前。フルネームは出さない
- 問い合わせ先: ゲーム専用のメールアドレス（会長が作る）。個人のアドレスは出さない

### 4.2 ゲーム側の準備（A）
1. **「このゲームについて」画面**: 設定画面（`openCloudSettings`）から開く。作った人（4.1の表記）、作った目的（越前そばを知って食べに来てもらう）、問い合わせ先、豆知識の出典一覧、素材のクレジット（BGM の Maniira さん／OpenTracks、地形データ、three.js）
2. **出典一覧**: `docs/story/content-review.md` の内容を、遊ぶ人向けに短くしてゲーム内で見られるようにする
3. **プライバシーポリシー**: Googleログイン（Firebase）とランキング（GAS）で何を預かるか、何に使うか、消し方、問い合わせ先。独立したページ（`privacy.html`）にして「このゲームについて」からリンク
4. **公開URL**: `/test/` から作品名へ。リポジトリ名の変更は会長の操作が必要（GitHub の Settings）。同じ github.io なので遊んだ記録（localStorage）は消えない。Firebase の承認済みドメインも同じまま。古い URL から新しい URL へ案内するページを残す

### 4.3 持ち込み資料（B）
1. **提案書（A4で1〜2枚、PDFにできる形）**: 自己紹介（高志高校の探究活動）／ゲームの紹介と画面写真／探究で調べたこと（出典つき豆知識）／観光連盟のガイドへどう案内しているか／お願い3つ／連絡先
2. **最初のメールの下書き**: 短く、提案書とゲームのURLを添える。宛先は観光連盟の問い合わせ窓口（送る前に会長が確認）

## 5. 会長がやること
- 担当の先生に話し、学校名を出してよいか、メールに入ってもらえるかを確認する
- ゲーム専用のメールアドレスを作る
- （URL変更をするなら）リポジトリ名を変える

## 6. 作る人に任せること
- 「このゲームについて」画面の見た目と置き場所の細部（既存のモーダルの見た目に合わせる）
- 英語表示の文面（既存の `T()` で両方用意）
- 提案書のレイアウト
- 新しいリポジトリ名の候補（例: `mugen-sobado`）。決めるのは会長
