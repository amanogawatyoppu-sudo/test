# クラウドセーブ（自動ログイン・Google連携）の準備手順

このゲームに「自動ログイン」と「Googleアカウントでのデータ引き継ぎ」を付けるには、
Google の無料サービス **Firebase（ファイアベース）** に、このゲーム用の場所を1つ作る必要があります。
作業はブラウザだけで終わります（パソコンに何かを入れる必要はありません）。所要時間は15分くらいです。

> 準備が終わるまでは、ゲームは今までどおり動きます（記録はその端末だけに保存）。

---

## できるようになること

| いつ | どうなるか |
|---|---|
| はじめて遊ぶ | 登録画面なしで、裏で自動的に「ゲスト」としてログインする |
| 2回目以降 | 何もしなくても前回の続きから遊べる（記録はクラウドにも自動保存） |
| 設定 →「Googleアカウントと連携」 | ゲストのセーブがGoogleアカウントに紐付く。機種変更しても、同じGoogleでログインすれば続きから |

引き継がれるのは、端末に保存している記録すべてです（リズムモードの自己ベスト、言語・BGMの設定、今日のそばの記録、ストーリーの進み具合など）。
**番付とガチャ（そば粉・職人）は今までどおり GAS に保存**されています。ただしパスワードはもういりません。ゲームが自動で作る合言葉（キー）でログインし、そのキーもクラウドセーブに入るので、Google連携すればガチャの職人・そば粉も別の端末に引き継げます（下の「今のセーブとの関係」を参照）。

---

## 手順1：Firebase のプロジェクトを作る

1. https://console.firebase.google.com を開き、Googleアカウントでログインする
2. 「プロジェクトを作成」（または「Firebase プロジェクトを始める」）を押す
3. 名前を入れる（例：`mugen-sobado`）→ 続行
4. 「Google アナリティクス」は**オフ**で大丈夫 → 「プロジェクトを作成」
5. 少し待って「続行」を押すと、プロジェクトの画面が開く

## 手順2：ゲーム（ウェブアプリ）を登録して、設定の値をもらう

1. プロジェクトの画面の真ん中あたりにある **`</>`（ウェブ）** のマークを押す
2. アプリの名前を入れる（例：`無限そば道`）。「Firebase Hosting」のチェックは**付けない** → 「アプリを登録」
3. 画面に次のようなコードが出る。この `{ }` の中身が必要な値:

   ```js
   const firebaseConfig = {
     apiKey: "AIza....",
     authDomain: "mugen-sobado.firebaseapp.com",
     projectId: "mugen-sobado",
     storageBucket: "mugen-sobado.firebasestorage.app",
     messagingSenderId: "1234567890",
     appId: "1:1234567890:web:abcdef..."
   };
   ```

4. このリポジトリの **`js/firebase-config.js`** を開き、空欄 `""` に上の値をそれぞれ貼り付けて保存する
   （GitHub の画面なら、ファイルを開いて鉛筆マーク → 書き換え → 「Commit changes」）

> 💡 この値は「どのFirebaseにつなぐか」を示す住所のようなもので、**秘密の鍵ではありません**。
> ゲームの中に書いて公開して大丈夫です。勝手に書き換えられないように守るのは、手順5の「ルール」です。

## 手順3：ログイン方法を2つ有効にする

1. 左のメニュー「構築（Build）」→ **Authentication** → 「始める」
2. 「Sign-in method（ログイン方法）」のタブで:
   - **匿名（Anonymous）** を選んで「有効にする」→ 保存 … 自動ログイン（ゲスト）用
   - **Google** を選んで「有効にする」→ サポート用メールに自分のアドレスを選ぶ → 保存 … 引き継ぎ用

## 手順4：ゲームを置いているサイトのアドレスを許可する

Googleログインは、許可したサイトからしか使えません。

1. Authentication の「**設定（Settings）**」タブ →「**承認済みドメイン**」
2. 「ドメインを追加」で、ゲームを公開しているアドレスのドメイン部分を追加する
   - GitHub Pages なら `amanogawatyoppu-sudo.github.io`
   - 独自ドメインならそのドメイン
   - （`localhost` は最初から入っているので、手元での確認はそのままできる）

## 手順5：データベースを作って、守りのルールを入れる

1. 左のメニュー「構築」→ **Firestore Database** →「データベースを作成」
2. 場所（ロケーション）は **`asia-northeast1`（東京）** を選ぶ（あとから変えられないので注意）
3. 「本番環境モードで開始」を選んで作成
4. できたら上の「**ルール**」タブを開き、中身をすべて消して、このリポジトリの **`firestore.rules`** の中身をまるごと貼り付け →「**公開**」

このルールの意味:
- ログインした人は、**自分のユーザーIDの書類（`users/自分のID`）だけ**読み書きできる
- 他人のセーブは読むことも書くこともできない
- 決まった形以外のデータや、項目が多すぎるデータは受け付けない
- セーブの削除はゲームからはできない（消すときは Firebase の画面から）

## 手順6：確かめる

1. ゲームを開く（最初の1回は少し時間がかかることがあります）
2. タイトル画面の下の **「⚙ 設定」** を押す →「いまは **ゲスト** で遊んでいる」と出れば自動ログイン成功
3. Firebase の Authentication →「Users」に、プロバイダが空欄（匿名）のユーザーが1人増えている
4. 少し遊んでから Firestore Database →「データ」を見ると、`users` の中に書類ができている
5. 設定から「Googleアカウントと連携」を押してGoogleを選ぶ →「連携できた！」と出れば完了
6. 別のブラウザ（またはスマホ）で開き、設定 →「Googleアカウントと連携」→ 同じGoogleを選ぶ
   →「このGoogleアカウントには、別の端末のセーブがすでにある」と出るので「切り替える」→ 続きから遊べる

## 今のセーブ（GAS）との関係

| データ | 保存場所 | 変わるか |
|---|---|---|
| リズムモード自己ベスト・設定・今日のそば・ストーリー進行など（端末に保存していたもの） | 端末＋**Firebase（新）** | 自動でクラウドにも保存され、Google連携で引き継げるようになる |
| 番付（30秒・60秒・無限・ランクマ・今日のそば） | GAS（今まで通り） | 変えない |
| ガチャ・図鑑（そば粉・職人） | GAS（中身は今まで通り） | ログインは自動（名前を決めるだけ）。自動ログインのキーは Firebase にも入るので、Google連携で引き継げる |

**なぜ番付とガチャは GAS に残すのか：** Firebase の「自分のデータは自分で書ける」ルールだと、
そば粉の枚数やガチャの結果をプレイヤーが自分の端末から書き換えられてしまいます（ズルができる）。
今の GAS はサーバー側でガチャを引いて記録しているので、ズルができません。ここは今の仕組みのままが安全です。

**ガチャのログイン（2026-11-25〜）:**
- はじめての人は、職人の名前を決めるだけ。ゲームが端末で長いランダムな合言葉（キー）を作り、GAS の players シートの「キー」列に登録する。次からはキーで自動ログイン（パスワードなし）。
- キーは端末の `sobamichi_player` に入るので、Firebase のクラウドセーブにも自動で入る。→ Google連携すれば、別の端末でも同じ職人になる。
- Firebase が準備中のあいだも、自動ログインとガチャはその端末で動く（ブラウザのデータを消すと戻れなくなるので、準備ができたらGoogle連携をすすめる）。
- 前に「名前＋パスワード」で遊んでいた人は、一度だけ「前のデータを引き継ぐ」で名前とパスワードを入れれば、そば粉・職人がそのまま引き継がれ、次から自動ログインになる。前のパスワードも消えずに残る。
- ズル防止は今まで通り（ガチャはサーバーで引く）。

## 技術メモ（開発する人向け）

- npm やビルドは不要。Firebase は CDN（`https://www.gstatic.com/firebasejs/11.0.2/...`）から ES モジュールとして読み込む。
- `js/cloud-save.js` が `localStorage` の `sobamichi_` で始まるキーへの書き込みを見張り、3秒待ってまとめて Firestore の `users/{uid}` に保存する（タブを閉じる・裏に回すときは即保存）。新しいキーを足しても自動で同期対象になる。`sobamichi_api`（一時メモ）と `sobamichi_cloud_meta`（管理用）は除外。
- 起動時はクラウドと端末の「最後に変更した時刻」を比べ、クラウドの方が新しければ端末に書き戻して1回だけ再読込する。
- 匿名アカウントを Google に紐付けても**ユーザーIDは変わらない**ので、セーブはそのまま。紐付け先の Google がすでに別のIDで使われていた場合は、確認のうえそちらにログインし直し、そのセーブで端末を上書きする（ゲスト側のセーブは使われなくなる）。
- ほかの処理からは `window.SobaCloud`（`uid`, `isGuest`, `ready` など）と `sobamichi:cloud-ready` イベントで状態がわかる。
- `js/firebase-config.js` の `apiKey` が空なら何もしない（設定画面には「準備中」と出る）。
- 注意：Safari などはしばらく開かないとサイトのデータを消すことがあり、そのときゲストアカウントは戻せない。大事なセーブはGoogle連携をすすめる。
